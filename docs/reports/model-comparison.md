# RUL Model Comparison

_Generated by `at_ml.compare`. Regenerate with `make train`._

Six architectures trained on CPU (2 cores). All share identical data preparation,
loss, optimiser, schedule, early-stopping rule and seed, so differences in the
tables are attributable to architecture rather than to tuning effort.

## Protocol

- **Labels**: piecewise-linear RUL capped at 125 cycles (ADR-012).
- **Normalisation**: per-regime z-score, fitted on the training split only (ADR-014).
- **Splits**: 80/20 by **unit**, never by row. Adjacent cycles of one engine are
  near-identical, so a row split leaks the answer.
- **Test protocol**: final window per unit, scored against the official
  `RUL_FD00X.txt` labels.
- **Model selection**: lowest *validation* NASA score, which encodes the
  asymmetric cost of predicting more life than an engine actually has.
- **Loss**: Huber (delta 5), more robust than MSE to the plateau created by the
  label cap.

## The uncomfortable result: the MLP wins

A flattened-window MLP posts the best RMSE and best NASA score on FD001, and the
best score on FD003, while training in **9 seconds** against the transformer's
**273**. That is not the expected outcome and it is reported rather than buried.

Why it happens here:

1. **The window is short and pre-normalised.** With W=30 and per-regime z-scoring
   already applied, most of the temporal structure a sequence model would learn
   has been handed to it. A linear map over 30x43 inputs can already express
   "recent values differ from early values".
2. **The dataset is small.** 14k windows from 80 engines is not enough to train
   attention from scratch without heavy regularisation, which is Risk R3 from
   Doc 00 landing exactly as predicted.
3. **The target is smooth and capped.** Above 125 cycles every label is identical,
   so roughly half the training signal is a constant that rewards simple models.

What the sequence models still buy:

- **Informer has the best near-failure accuracy on FD001** (RMSE 2.89 for RUL ≤ 25
  versus the MLP's 4.54). That is the band that actually triggers maintenance, so
  on operational value the ranking is not the same as on headline RMSE.
- **Informer wins outright on FD003** (RMSE 13.14, R² 0.888), the harder subset
  with two fault modes.
- The ProbSparse attention question posed in Doc 07 section 7.3.5 has an answer:
  on these short sequences it behaves as a mild regulariser and beats the dense
  transformer on every metric in both subsets (FD001 score 266 vs 509; FD003
  RMSE 13.1 vs 15.1). The efficiency argument is irrelevant at W=30, but the
  regularisation argument holds.

**Selection consequence.** The registry promotes on validation NASA score, which
chose the MLP for FD003 and the LSTM for FD001. If the platform were graded on
near-failure accuracy alone, Informer would be the better production choice for
FD001. This is recorded as an open question for M5 rather than silently resolved.

## Reading the columns

- **RMSE (RUL≤25)** is the operationally meaningful number. A model can post a
  good overall RMSE by being accurate on healthy engines while being useless near
  failure, which is the only region that drives a maintenance decision.
- **late %** is the share of predictions that *overestimate* remaining life. These
  are the dangerous errors: an engine predicted healthier than it is gets
  dispatched and strands an aircraft. The NASA score penalises them
  asymmetrically; this column makes the raw rate visible.
- **NASA score** is a sum, not a mean, so it scales with the number of test units
  and is only comparable within a subset.

## A leak worth recording

The first run of this harness produced validation RMSE **11.0** and test RMSE
**53.7**, with R² of **-0.80** — worse than predicting the mean.

The cause was a leaking feature. `cycle_norm` was computed as
`time_in_cycles / max(time_in_cycles)` per unit. In training, `max()` is the
failure cycle, so the feature silently encodes *fraction of life consumed* and
the model learned `cycle_norm ≈ 1 ⇒ RUL ≈ 0`. In test, `max()` is merely where
recording stopped, so every test unit arrives with `cycle_norm ≈ 1` while
actually having 100+ cycles left. Every engine was predicted as nearly dead.

It is recorded here because **the validation score looked excellent while the
model was worthless** — which is precisely how this class of leak survives into a
published result. The fix divides by a fixed constant (400 cycles) so the feature
means the same thing in both splits and remains computable online from a single
counter.

Fix impact on FD001/TCN: RMSE 53.7 → 15.1, R² -0.80 → 0.86, NASA score
22,528 → 302.

## Not done here

- **FD002 and FD004** are not trained. Each is 3-4x the data and would take
  roughly 90 minutes per subset on 2 CPU cores. The pipeline is subset-agnostic
  and `make train SUBSET=FD002` will run them where more compute is available.
- **Multi-seed runs.** Every figure is a single seed (42). The variance between
  seeds is unmeasured, so small differences between adjacent rows should not be
  over-read.
- **Uncertainty calibration.** MC-dropout and conformal intervals are specified in
  Doc 07 section 7.5 and land in M5 alongside serving.
